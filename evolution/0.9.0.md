# Version 0.9.0

## Focused improvement: temporal correctness

Added `references/temporal-correctness-review.md` as a focused playbook for changes involving clocks, timestamps, expiry, TTLs, leases, scheduling, delayed work, retries, late events, and ordering.

Why this matters:
- Existing guidance covered concurrency and rollout risks, but temporal semantics were distributed across several sections.
- Time-dependent defects often pass ordinary happy-path tests and appear only at exact boundaries, after restart, under clock adjustment, or when delayed/duplicate/out-of-order work arrives.
- The reference turns those risks into explicit, deterministic review questions without expanding the main checklist.

The reference emphasizes clock selection, timestamp meaning, expiry boundaries, durable scheduling, catch-up storms, late retries, sequence/version protection, and controllable-clock tests.
